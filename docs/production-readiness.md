# Что проверить перед реальным запуском ChronoCampus

Текущая версия рассчитана на учебную демонстрацию. В реальном вузе её ещё не проверяли.

**Развёртывание и хранение.** Нужны постоянные веб-хост и SQL Server с устойчивым хранилищем и управлением секретами. Перед запуском нужно проверить HTTPS, защищённые cookies, доступность портала, почты и фоновых процессов после перезапуска, а также переход на актуальную схему с учётной записью для миграций.

**Резервное копирование.** Нужно определить расписание копий, место хранения, срок хранения и ответственных. Учение должно показать, сколько данных и времени теряется при аварии, восстанавливается ли копия в отдельном экземпляре и доступны ли после восстановления пользователи, расписания и публикации.

**Вход под нагрузкой.** Сейчас проверка пароля выполняется под общим `lock_revision`, лимит в 100 попыток с IP учитывает успешные входы, а приложение за прокси не определяет IP клиента. Нужно сократить время удержания замка, измерить вход и влияние на остальные записи под нагрузкой, настроить доверенные прокси, затем проверить лимиты для общих сетей и случай поддельных заголовков.

**Сброс пароля.** Письмо сброса отправляется вне надёжной очереди. Нужно проверить повторную доставку после простоя SMTP или перезапуска и одноразовое использование ссылки. Ограниченной учётной записи SQL Server требуется точечный `EXECUTE` на процедуру сброса. Её права нужно проверить отдельно от прав владельца схемы.

**Уведомления.** Текущий клиент опрашивает данные расписания за семестр. Для реального запуска нужен курсор событий с догрузкой пропущенного после переподключения. Проверка должна измерить объём запросов под нагрузкой и подтвердить порядок, отсутствие дублей и соблюдение прав доступа.

**Срочная отмена.** Нужно согласовать отдельный процесс срочной отмены, роли, обязательность последующей отработки и способ оповещения. Приёмочный сценарий должен включать отмену занятия в день проведения и отдельный перенос на новую дату.

**Полнота нагрузки.** Синтетические данные проверяют работу генератора. Нужен утверждённый вузом набор по семестру с нагрузкой, преподавателями, помещениями, подгруппами и календарём, включая заочную форму. По нему нужно сверить часы и обязательные занятия каждого набора, исключения календаря и полную публикацию.

**Официальный список студентов.** Строгий режим и очередь декана для новых регистраций реализованы. Для запуска нужно согласовать источник списка, обновление и проверяемый идентификатор студента, правила разбора полных тёзок и случаи чужой или повторной регистрации. Учётные записи, созданные до включения режима, потребуют подтверждения перед переходом. Нужно проверить эти сценарии на утверждённом списке и определить, кто исправляет ошибки.
