# Вклад nemsime в этап разработки ChronoCampus

Этот документ описывает результаты этапа в ветке `codex/chronocampus-system`, чтобы участники команды могли отделить исходный проект от последующей реализации. Сравнение зафиксировано на 24 октября 2026: исходная точка `828e271`, результат реализации `7e12b5e`.

Требования и решения согласованы с nemsime; реализация и проверки выполнены в совместной работе с Codex. Коммиты этого этапа имеют Git-автора `nemsime`. Это описание объёма переданной работы, а не утверждение об авторстве всех ранее существовавших файлов. Вклад остальных участников здесь не распределяется.

## Что уже было в проекте

На исходной точке существовали React/TypeScript/Vite интерфейс-прототип, SQL Server схема и справочники, университетские Word-файлы, начальная FastAPI-связка и чтение групп через `GET /api/groups`. Авторизация и большинство экранов оставались демонстрационными. Это состояние описано в README коммита `828e271` и [историческом обзоре](Preview.md).

Нынешняя система развивает этот репозиторий: полезные каталоги сохранены, схема обновляется миграциями, новый работающий интерфейс подключён через `frontend/src/system`. Старые компоненты прототипа сохранены как справочный код.

## Требования и решения, внесённые nemsime

- Уточнены реальные правила вуза: сетка звонков, дополнительные пары по разрешению, числитель/знаменатель, наборы и вложенные подгруппы, ограничения преподавателей и аудиторий.
- Разделены учебный год, семестры, периоды занятий и экзаменационные месяцы; оговорены различия праздничных отмен и чрезвычайных отработок.
- Определены семестровые часы по видам занятий, заранее назначенные преподаватели, приоритет уменьшения окон, сохранение закреплений и запрет публикации неполного расписания.
- Согласованы React/TypeScript, модульный FastAPI, SQL Server с миграциями и OR-Tools CP-SAT; определён полный цикл от нагрузки до опубликованного личного расписания.
- Заданы RU/HY/EN, локальные роли и восстановление доступа, личные заметки к конкретному занятию, обращения с ответами и статусами, вымышленные демонстрационные аккаунты.

Подробные правила и ещё не подтверждённые параметры находятся в [requirements.md](requirements.md). Неизвестные значения не выдаются за утверждённую политику вуза.

## Чем подтверждён результат и что остаётся

В заключительной проверке реализации прошли 32 теста, включая отдельно включаемую проверку конкурентной публикации на SQL Server, статическая проверка Python, TypeScript typecheck и production build. На демонстрационных данных опубликованы полные расписания для 960 очных и 120 заочных конкретных занятий. Проверены пользовательские сценарии входа, заметок, обращений, справочников и переключения языков. Методика, окружение и ограничения приведены в [verification.md](verification.md); эти результаты относятся к указанному состоянию реализации.

Для реального внедрения остаются подтверждение точных университетских параметров и данных, настройка и проверка университетской почты и размещения. Не заявлены как готовые: автоматическая расстановка экзаменов, импорт Word, Microsoft SSO, общие уведомления, работа нескольких API-процессов и изменение уже материализованного учебного плана на месте. Полное допустимое расписание не означает доказанного минимума всех мягких штрафов.
